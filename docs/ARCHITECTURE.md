# Architecture and trust boundary

Living Context's supported reference is a process-local record and planning API. It models what a revision-aware learned-context system would need to know before changing its active corpus. It does not train or serve learned artifacts.

## Data path

1. A trusted owner adds `DocumentRevision` records to the append-only `Catalog`. Each has a stable document ID, unique revision ID, ISO `as_of` date, content, and edit kind. `revision_at` supports explicit historical lookup.
2. The owner stages a **complete** `VersionedCorpus` candidate. `stage_changes` merges edits with the active snapshot; `stage` rejects an omitted live document unless deletion is explicit. The frozen candidate is invisible to `serve`.
3. For research comparisons, `plan_refresh` computes a `RefreshPlan` from the old and new snapshots and their exact pre-edit revision map. Arm 4 selects changed live documents. Arm 5 follows transitive, caller-declared `TrainingEdge` co-training relationships from the **old** revisions and maps affected documents to their new rebuild revisions. Arm 6 uses arm 4's rebuild set and marks those documents for text fallback. A deletion yields a retirement set.
4. The owner performs whatever checks the application requires and supplies an actual Boolean to `admit`. For an artifact-bearing candidate, the optional `verify_artifacts` path checks a complete manifest and supplied bytes, then returns a typed `ArtifactAdmissionReceipt`. The owner passes it to `admit` along with the Boolean. A false result leaves the active snapshot unchanged. A true result revalidates the candidate, rejects stale bases and rollback, and switches the process-local active snapshot under a lock. `serve` returns one admitted immutable snapshot; an explicit generation accesses retained history.

The planner returns data. It neither builds artifacts nor runs a scheduler or a model. The graph stores asserted edges; it does not observe or infer training batches. `checks_passed=True` remains a trusted owner assertion on the original Boolean path. The optional receipt path checks lowercase SHA-256 artifact digests and exact live source revisions, requires target coverage for every live document, and binds the receipt to the candidate generation, candidate bytes, copied artifact bytes, copied source text, and this corpus instance. Unchanged artifacts may be reused from earlier generations when their source revisions still match exactly. Rejected admissions discard their receipt; the owner can explicitly discard an abandoned receipt. The digest checks consistency, not the identity of the caller or whether training actually used the claimed sources.

The local [`TextReader`](../src/living_context/text_reader.py) is one identified CLI caller's model-free retrieval path. Every returned text record names an admitted generation and revision. Explicit historical reads carry `current=False`; a retired document has no current read. Its fallback method requires the caller's expected generation to equal the active generation and the admitted revision to match the plan's rebuild target. A pending candidate's text cannot satisfy that request until admission. `current` describes the snapshot at the read check, not a promise that it stays current forever. This is text retrieval, not language generation or learned-artifact serving; the caller must preserve the generation and revision labels when displaying or using results.

## Why these boundaries matter

A complete candidate prevents an incidental partial map from silently dropping a live document. Old-revision dependency closure avoids treating a new, not-yet-trained revision as the source of historical co-training impact. Retained generations make current and historical reads explicit. These choices make the small reference testable without assuming a particular model or storage format.

The atomicity claim covers readers of one `VersionedCorpus` object while a single trusted owner serializes catalog mutations. The catalog itself is not a concurrent transaction service. There is no durable store, distributed admission, untrusted-writer defense, automatic dependency discovery, learned serving, persisted KV cache, or model unlearning. The study's embedding soft prefixes recompute activations at inference and are separate from the reference planner. The optional artifact receipt keeps a process-local copy of the verified bytes until admission or explicit discard; it is not a durable provenance record.
